# P1-01a — Owner Move-out / Lease Closure (DEV)

**2026-11-03 status:** Implemented and tested for Apartment DEV; P1-01b repairs/maintenance and P1-03 partial-period billing and security deposits remain **not completed**.

## API and UI

- POST /v1/properties/:propertyId/leases/:leaseId/move-out with JSON:
  - endExclusive: ISO calendar date, after the original lease start and no later than current Asia/Bangkok calendar date
  - roomDisposition: AVAILABLE or MAINTENANCE
  - confirmedHandover: true (required)
- An authenticated ACTIVE organization **OWNER** must act, scoped to the correct property and lease. MANAGER and unrelated users are denied. A SUPER_ADMIN without an owner membership cannot silently bypass this financial/occupancy action.
- Owner UI in Rooms shows a move-out form for currently active leases, date, room disposition (MAINTENANCE by default), and explicit irreversible confirmation.

## Strict settlement/tenant safety gates

All conditions must hold before commit:

1. The lease is ACTIVE and the property room is OCCUPIED; the day is a real calendar date after lease start and not in the future.
2. WATER and ELECTRIC readings are both present at the **exclusive** end boundary. Operators must complete meter records first.
3. There is an **ISSUED final invoice whose periodEnd equals endExclusive**. All existing issued invoices for the lease must end no later than endExclusive. Partial-period final invoices are not supported; P1-03 must add them before midcycle move-outs can close.
4. No pending payment claims or pending financial adjustment requests for that lease's issued invoices, and **every issued invoice has zero outstanding balance** calculated from immutable ledger and credit/reversal entries.
5. The OWNER confirms physical handover. Security deposits and statutory/legal settlement have **not** been implemented: staff must manually verify these before closing, without describing it as automated deposit settlement.

The transaction acquires a PROPERTY row lock (same as invoice issuing), then lease and room locks to serialize concurrent operations. On success it sets lease status ENDED and endDate, changes room to AVAILABLE or MAINTENANCE (not always available), revokes outstanding lease invitations and LINE notification consents, marks queued/retry/sending LINE Outbox entries DEAD, and creates an immutable LEASE_MOVED_OUT audit event. Historical invoices, payment claims, ledger, financial adjustments, audit, and tenant data are **not deleted or rewritten**.

Repeating a move-out returns 409. A new lease can be created when the room is AVAILABLE. Historical tenant invoice access after ending an active lease is not yet a full former-tenant portal workflow and belongs to P5-06.

**No real LINE messages, bank reconciliation, refunds, deposit payouts, or legal documents are sent/generated by this endpoint.**
